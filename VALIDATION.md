## November 6 map-boundary freeze correction

Reproduced synchronous 3D rebuild stalls in the invisible software-WebGL map-crossing fixture: 276.4–417.3 ms for one render call, including repeated backtracking. Each new 36 × 36 snapshot previously rebuilt both scenery/floor textures, read back grouped artwork repeatedly, sorted palettes and uploaded the whole scene before the game loop could continue.

The renderer now shares its original artwork atlas, builds floor/front geometry directly from those textures, reuses bounded CPU silhouette templates, computes cap colors with a histogram, shares identical animation phases, and splits GPU buffer uploads. Ordinary gameplay boundaries prepare new scene bundles cooperatively with a roughly 4 ms work budget per frame. Existing surroundings remain visible with the coordinate shift applied to geometry, actors, labels and pointers until the new bundle is ready. A local view revision prevents chunked visual metadata from applying the boundary shift twice. Three recent complete scene bundles are cached; rapid returns cancel unfinished work and use the cached scene. Template storage is capped at 256 entries/16 MB, and leaving 3D frees pending/cached GPU resources. Custom-house material painting also uses a single pixel buffer instead of thousands of canvas draw calls. Initial 3D startup still loads its shared artwork; script/quest teleport freezes were not removed.

## November 7 explicit surface classification and property-aware painting (Priority 1)

Root causes of floor-tiles-rendered-as-walls were diagnosed with visual evidence sheets. The catalogue fallback promoted 13 textured tiles to walls from whole-collection upper-layer usage; separately, transparent floor decals (splatters, carpets, mosaics, pebbles, trapdoors, ground skeletons) rendered as upright slabs because catalogue classification is per tile ID while the original art supports different placements per cell. Mass reclassification would have been wrong: cliff textures such as 711 are frequently the foundation row of standing mountain faces.

Implemented explicit per-placement reclassification with predicted precedence: instance > map region assetProfiles > installation overrides > generated catalogue. scenery-profiles.js merges instance overrides before grouping, so a per-cell kind re-classifies exactly that placement, and instance opening/closed rules now reach wall geometry. The Studio Rendering profile repair panel enables surface type and opening rules at instance scope; the Structure Inspector reports the effective merged profile, its provenance (installation/map/instance contributions) and automatic classification source. A new Surface (3D) selector paints a per-cell surface kind with the next artwork paint; erase-painting removes the override; stale overrides die when their artwork disappears; overrides are capped at 1024 per map; the eyedropper samples the painted surface; 2D shows per-cell badges.

Rendering properties travel with the clipboard. Region and whole-object copies capture per-cell surface overrides, 3D heights/walls/wallTiles sub-grids and houses fully inside the span. Pastes default to transparent overlay (only clip-set values) with an explicit replace mode; instances deduplicate by cell, pasted houses take over the footprints they cover and receive unique identifiers, and both caps fail loudly. Collision, anchors and map connections remain independent of every visual paste.

New isolated checks: tools/test-instance-reclassification.cjs (precedence, unchanged automatic behaviour, idempotent transforms, morphology validation, inspector provenance) and tools/test-clipboard-visual.cjs (clipboard metadata, overlay vs replace, instance lifecycle, house takeover, caps). Regression: test-tile-assemblies, test-scenery-world (all 1,520 maps, unchanged source hash), test-editor-foundation, test-movement, smoke-test and test-studio-overhaul-ui all passed; test-scenery-all-ui rendered all 1,520 maps in both animation phases with zero WebGL errors. Original Classic data and collision remain untouched; all changes are additive visual metadata. Studio reload picks up the changes; no server restart is required because nothing on the server side changed.
